# 02 最低限の知識 — これだけ知っていれば会話が成立する

プログラミングの知識は要りません。**UE5の「用語」だけ**覚えてください。
指示を出すときに正しい単語を使えると、Claude Codeの精度が劇的に上がります。

---

## 1. フォルダ構造（Gitで事故らないために）

```
C:\UE\SpeedTest\
├── SpeedTest.uproject   ← ダブルクリックでプロジェクトが開く。これが本体
├── Content\             ← ★あなたの資産。モデル、マテリアル、レベル、Blueprint 全部ここ
├── Config\              ← 設定ファイル(.ini)。テキストなので Claude が読み書きできる
├── Saved\               ← ログ、オートセーブ、スクショ。★消してもいい
├── Intermediate\        ← 中間ファイル。★消してもいい
└── DerivedDataCache\    ← シェーダーキャッシュ。★消してもいい。数十GBになる
```

- **`Saved\` `Intermediate\` `DerivedDataCache\` は絶対にGitに入れない。** 数十GBになります
- **UE5が挙動不審になったら**: エディタを閉じて `Intermediate\` と `DerivedDataCache\` を削除 → 再起動。
  初心者が遭遇する不具合の半分はこれで直ります（再ビルドに時間はかかりますが安全です）
- **`Config\` はClaudeの得意分野**: テキストファイルなので直接読んで編集できます

## 2. レベル / アクター / コンポーネント

| 用語 | 意味 | たとえるなら |
|---|---|---|
| **Level（レベル／マップ）** | ゲームの舞台。1つのステージ | 映画のセット |
| **Actor（アクター）** | レベルに置かれる物すべて。車、木、ライト、カメラ | セットに置かれた小道具や役者 |
| **Component（コンポーネント）** | アクターを構成する部品 | 車というアクターの「車体メッシュ」「エンジン」「カメラ」 |

→ Claudeが正確に理解できます。

## 3. Blueprint / GameMode / Pawn / PlayerController

| 用語 | 意味 |
|---|---|
| **Blueprint（BP）** | ノードを線でつなぐビジュアルプログラミング。**UE5の主役** |
| **Pawn（ポーン）** | プレイヤーが操作できるアクター。**今回は「車」がこれ** |
| **PlayerController** | 入力（キーボード、パッド）を受け取ってPawnに伝える係 |
| **GameMode** | 「このレベルではどのPawnを、どのControllerで操作するか」のルール表 |

**理解すべきはこれだけ**:
> あなたがWキーを押す → **PlayerController** が受け取る → **Pawn（車）** に「前進しろ」と伝える
> → 誰が車で誰がコントローラーかを決めているのが **GameMode**

⚠️ **重要な制約**: Blueprintは `.uasset` というバイナリファイルです。
**Claude Codeはテキストエディタでこれを直接編集できません。**
だから **MCP接続（[`00-setup.md`](00-setup.md) STEP 8）が重要**です。MCP経由なら操作できます。

## 4. Material と Material Instance（★重要）

| 用語 | 意味 |
|---|---|
| **Material（マテリアル）** | 表面の質感の「設計図」。ノードで組む。**変更するとシェーダー再コンパイルが走って重い** |
| **Material Instance（マテリアルインスタンス／MI）** | 設計図から作った「調整可能なコピー」。**スライダーを動かすだけ。即座に反映** |

### 原則：**触るのは常に Material Instance の方**

Materialを直接いじると毎回シェーダーコンパイルで数十秒〜数分待たされます。
MIならリアルタイムで変わります。マテリアルを右クリック →「Create Material Instance」。

### 質感を決める3つの数値（これだけ覚える）

| パラメータ | 意味 | 効き方 |
|---|---|---|
| **Base Color** | 基本の色 | そのまま色 |
| **Metallic** | 金属かどうか | 0 = 非金属（プラ、布、石） / 1 = 金属。**中間値はほぼ使わない** |
| **Roughness** | 表面の粗さ | 0 = 鏡のようにツルツル / 1 = ザラザラ。**見た目への影響が一番大きい** |

車のボディを「磨かれた新車」にしたければ Roughness を 0.1〜0.2 に。
「くたびれた中古車」なら 0.5〜0.7。**ここを触るだけで印象が激変します。**

## 5. Lumen / Nanite / Virtual Shadow Maps（UE5が綺麗な理由）

| 技術 | 何をするか | なぜ綺麗になるか |
|---|---|---|
| **Lumen** | リアルタイム大域照明（GI）と反射 | 赤い壁の近くの床がほんのり赤くなる。**光が跳ね返る**。現実ではこれが起きているので、無いと途端に嘘っぽくなる |
| **Nanite** | 超高密度ポリゴンをリアルタイム描画 | 数千万ポリゴンの岩をそのまま置ける。**LODやポリゴン削減の作業がほぼ要らなくなった** |
| **Virtual Shadow Maps (VSM)** | 高解像度の影 | 影の輪郭が汚くならない。Lumenとセットで使う |
| **TSR / DLSS** | 低解像度で描いて綺麗に拡大 | **画質をほぼ落とさずfpsが上がる。** RTX3080ならDLSS推奨 |

**GT7やGTA5に「見た目で」近づける最大の武器がLumenです。** UE5で既定ONなので、あなたは既に使っています。

## 6. Post Process Volume（★見た目の半分はここ）

レベルに置く「画面全体の色と光の調整装置」。写真の現像に相当します。

| 設定 | 何が変わるか |
|---|---|
| **Exposure（露出）** | 画面全体の明るさ。**初心者の最重要項目**（下記） |
| **Color Grading** | コントラスト、彩度、シャドウ/ハイライトの色味。**映画っぽさはここ** |
| **Bloom** | 明るい部分が滲む。強すぎると安っぽい。控えめに |
| **Motion Blur** | 動きのブレ。速度感が出る |
| **Chromatic Aberration** | レンズの色収差。**ごく弱く入れると実写っぽさが出る** |

### ★オートエクスポージャーの罠

UE5は既定で**自動露出**がONです。カメラを暗い方に向けると勝手に明るくなり、明るい方を向くと勝手に暗くなる。
**これが「なんか安っぽい」の最大の原因。**

**直し方**: Post Process Volume の
`Exposure > Min Brightness` と `Max Brightness` を**同じ値**（例: 両方 1.0）にする。
これで露出が固定され、写真のように「明るい場所は明るく、暗い場所は暗い」画になります。

> ついでに、Post Process Volume の **`Infinite Extent (Unbound)` にチェック**を入れること。
> これが無いとボリュームの箱の中にいるときしか効果が出ません。初心者が必ず一度ハマります。

## 7. 空と光のセット（4点セットで覚える）

| アクター | 役割 | 無いとどうなるか |
|---|---|---|
| **Directional Light** | 太陽。角度と色温度 | 影が出ない |
| **Sky Atmosphere** | 物理ベースの空 | 空が単色で嘘っぽい |
| **Sky Light** | 空からの環境光 | 影の中が真っ黒に潰れる |
| **Exponential Height Fog** | 大気の霞 | 遠景に奥行きが出ない。**薄くかけるだけで劇的に良くなる** |

（+ **Volumetric Cloud** で立体的な雲）

**太陽の角度のコツ**: Directional Light の Rotation の **Y を -10〜-25度** くらいにすると低い太陽になり、
影が長く伸びて一気に映画的になります。真上（-90度）は最も平坦でつまらない絵になります。

## 8. Chaos Vehicle（車の物理）

UE5の車両システム。Day5で触ります。**全部が数値なのでClaude Codeの得意分野です。**

| パラメータ | 何が変わるか |
|---|---|
| **Engine Torque Curve** | 回転数ごとの力。低回転側を太くすると「ドンと出る」 |
| **Gear Ratios / Final Drive** | 加速重視か最高速重視か |
| **Suspension**（硬さ/ストローク） | 硬い＝スポーティで跳ねる / 柔らかい＝ふわふわ |
| **Tire Friction** | グリップ。上げると曲がる、下げると滑る（ドリフト） |
| **Steering Curve** | 速度ごとのハンドルの効き。高速で効きすぎると不安定になる |
| **Mass / Center of Mass** | 重心。低いほど安定、高いほど横転しやすい |

## 10. 性能の見方

エディタで **`（バッククォート）** キー → コンソールに入力：

| コマンド | 見えるもの |
|---|---|
| `stat fps` | フレームレート |
| `stat unit` | **Frame / Game / Draw / GPU の内訳。どこが重いかが分かる** |

`stat unit` で **GPU** が一番大きければグラフィック負荷、**Game** が大きければCPU/ロジック負荷。
RTX 3080 なら 1440p で 60fps を目安に。

> **今週は fps が落ちても気にしないでください。** 最適化は専門技術で、1週間の範囲外です。
> 30fps でも「絵が綺麗」なら今週の目標は達成です。

## 11. Git LFS（なぜ必要か）

`.uasset`（UE5のファイル）は3Dモデルや画像を含む巨大バイナリです。
普通のGitはテキスト向けで、変更のたびにファイル全体を丸ごと保存します。
→ 100MBのモデルを10回編集したら、リポジトリが1GBに膨れます。

**Git LFS** はこれを別管理して、リポジトリ本体を軽く保ちます。
UE5でGitを使うなら必須。設定は [`../templates/UE5_gitattributes.txt`](../templates/UE5_gitattributes.txt) に用意してあります。
