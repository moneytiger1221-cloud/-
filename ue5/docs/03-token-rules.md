# 03 トークン運用ルール — Proプラン($20)を焼き切らないために

## 前提：Proプランの制限

Claude Pro は **5時間ごとのセッション上限** と **週次上限** の2段構えでメーターが回ります。
Claude Code、Web、デスクトップ、モバイルは**同じ枠を共有**しています。

つまり **「Webチャットで長話をすると、PCのClaude Codeで使える分が減る」** ということです。
1週間スプリントを完走したいなら、以下のルールを守ってください。

---

## ルール1. 既定は Sonnet。Opus は詰まったときだけ

Claude Code内で `/model` で切り替えられます。

| 作業 | 使うモデル |
|---|---|
| 数値調整、スクリプト生成、決まった手順の実行 | **Sonnet** |
| 設計判断、原因不明のエラー、「どう作るべきか」の相談 | Opus |

Day5の車両パラメータ調整のような作業は Sonnet で十分です。

---

## ルール2. 1セッション1タスク。終わったら `/clear`

**これが一番効きます。**

Claude Codeは会話が長くなるほど、毎ターン過去のやり取り全部を読み直します。
2時間続いた会話の21回目の質問は、1回目の10倍以上のトークンを消費します。

```
Day2のライティング作業 → 終わったら /clear
Day2のスクショ撮影 → 終わったら /clear
```

**「話が変わったら `/clear`」を癖にしてください。**

---

## ルール3. `CLAUDE.md` に前提を書いておく

`C:\UE\SpeedTest\CLAUDE.md` にプロジェクトの前提を書いておくと、Claude Codeが毎回自動で読みます。
**「UE5.8を使っていて、RTX3080で、車のゲームを作っていて…」を毎回説明しなくて済みます。**

雛形: [`../templates/CLAUDE.md`](../templates/CLAUDE.md) をコピーして使ってください。

---

## ルール4. `Content/` をClaudeに読ませない（★重要）

`.uasset` はバイナリファイルです。Claudeが読んでも意味不明な文字列にしかならないのに、**巨大**です。
1回の事故で数万トークンが消えます。

対策: `C:\UE\SpeedTest\.claude\settings.json` に除外設定を入れる。
雛形: [`../templates/claude-settings.json`](../templates/claude-settings.json)

**やってはいけない指示の例:**
- ❌ 「Contentフォルダの中身を全部見て」
- ❌ 「プロジェクト全体を調べて」
- ✅ 「`Config/DefaultEngine.ini` の Lumen 関連の設定を見て」

---

## ルール5. ログは全文を貼らない

UE5のログは数千行あります。全部貼ると1回で大量に消費します。

- ❌ Output Log を全選択してコピペ
- ✅ **赤いエラー行と、その前後3行だけ**を貼る

「エラーが出た」だけでも、まずスクショ1枚の方が安上がりなことが多いです。

---

## ルール6. MCPツールは必要な分だけ有効化する

Unreal MCP + AllToolsets は **30以上のツールセット、数百のツール** を提供します。
これらの定義は**毎ターン文脈に読み込まれます**。全部有効だと、何も頼んでいなくてもトークンが減ります。

**接続できたら、まず Claude Code で `/mcp` を確認し、
使っていないツールセットを無効化できないか調べてください。**
Day2〜4なら actors / materials / lighting あたりがあれば足ります。

（具体的な絞り方は接続後に分かるので、分かった時点でこのファイルに追記します）

---

## ルール7. 繰り返す作業は Python スクリプト化する（★効果大）

| 方式 | コスト |
|---|---|
| MCP経由でClaudeにエディタ操作させる | **1回操作するたびにトークンを消費** |
| ClaudeにPythonスクリプトを書かせる | **書くのは1回。実行は何度でもタダ** |

同じ作業を2回以上やるなら、**必ずスクリプトにしてください。**

このリポジトリの [`../scripts/`](../scripts/) がその実例です。
`setup_lighting.py` は「ライトを6個置いて設定する」作業ですが、
MCP経由でやると毎回それなりのトークンを使います。スクリプトなら実行は無料です。

---

## ルール8. 大きい作業は Plan Mode で

Claude Code で **Shift+Tab** を2回押すと Plan Mode に入ります。
Claudeが「何をどうするか」の計画だけ出して、**実行はしません**。承認してから動きます。

**手戻りが一番高くつきます。** 「思ってたのと違う」を10回やるより、計画を1回確認する方が遥かに安い。

---

## ルール9. 辛口レビューの運用（★あなたの希望を実現するための調整）

あなたが希望した **「サブエージェントが忖度なしで辛口評価 → 100点が出たら確認」** について、
正直に言っておくべきことが2つあります。

### 問題1: 毎回やると週次上限に届く
サブエージェントは独立した文脈を持つので、1回の起動コストが大きい。
変更のたびに走らせると、実装に使える分が無くなります。

### 問題2: 「100点が出るまで回す」は原理的に終わらない
レビュアーは無限に粗を探せます。何を出しても必ず何か指摘できてしまう。
**終了条件が無いループになります。**

### だからこうします

| 調整 | 内容 |
|---|---|
| **頻度** | 各Dayの終わりに1回だけ。変更のたびには走らせない |
| **ラウンド上限** | **2回まで。** 2回で残った指摘は「次の日に送る」か「仕様として許容」かをあなたが決める |
| **採点基準** | 主観ではなく [`04-rubric.md`](04-rubric.md) の配点表で固定 |
| **入力** | **スクリーンショット** + 変更点の要約 + 数値設定ファイルのみ。プロジェクト全体は読ませない |
| **参照** | `C:\UE\reference\` の目標画像と比較させる |

**辛口さは維持したまま、終わる仕組みにしてあります。** 質は落ちません。むしろ
「スクショを見て、参照画像と比較して、決まった配点で採点する」方が、
漠然と「評価して」より遥かに厳しく具体的な指摘が出ます。

---

## ルール10. Webチャットと Claude Code の使い分け

| 用途 | どっち |
|---|---|
| UE5の実作業（エディタ操作、ファイル編集） | **PCのClaude Code** |
| 「どう作るべき？」の相談、調べ物、手順書の更新 | **Webチャット（ここ）** |
| エラーの原因調査 | まずClaude Code。手に負えなければWebへ |

**両方が同じ枠を共有していることを忘れずに。** Webでの雑談は、そのまま実装時間を削ります。
